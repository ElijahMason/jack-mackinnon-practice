Software that assumes the room was designed.

Jack writes the software for the teams whose rooms he builds. The program may trust the labels, the screen count, and the clear desk. It may not invent a name the cable does not carry. The desk is part of the system.

He does not hand over a tool and leave the furniture to chance. The install and the code are one practice. You can trace a port from the label on the desk to the same name on the screen.

What the software is allowed to assume

  1. The port name in the tool matches the label at both ends of the cable.
  2. The screen count in the tool is the screen count on the desk, including an arm that stays inside the edge.
  3. A status the tool shows has a place to land on the bench, not only a row you cannot find.
  4. The workflow matches how paper, parts, and files actually move across that desk.

What he refuses to pretend

The interface is not a substitute for a route. If the cable is unlabeled, the software does not guess. If the desk cannot be cleared, the workflow does not assume a clear surface. Fix the room, then let the program rely on it.
